# ADR 0003: Pin the durable document-generation TypeScript contract

- Status: Accepted
- Date: 2026-07-27
- Decision owner: Job Seeker Copilot

## Context

DOCGEN-16 cannot safely migrate the browser to draft preview and explicit
approval while the client still imports an ignored, machine-local generated
client. Document Generation Gateway 1.4.0 now owns a reviewed durable operation
that accepts an owner-authorised `savedJobId`, resolves canonical Job/Profile
evidence server-side, uses an idempotency key and creates the Application
Tracker record only after exact-draft approval.

The retained legacy generation operation accepts browser job content. It is not
an approved contract for the beta journey.

## Decision

Pin the exact Gateway 1.4.0 OpenAPI document from producer merge
`1d03324c2b80fbe44ebb5faccbc158334969464a` in the client contract lock.
Generate its Angular client with the already pinned OpenAPI Generator 7.23.0
into the client's canonical ignored generated root:
`src/app/api/document-generation-gateway`.

Contract policy requires the durable start, read/cancel, approval and download
paths. It also proves that start accepts only `savedJobId` plus
`Idempotency-Key`, has no browser job body and has no `X-User-Id` parameter.
`npm run api:generate:verify` generates all pinned clients twice in isolated
temporary directories and compares every generated byte.

## Consequences

The client can now reproduce the Gateway TypeScript boundary from a clean clone
without a sibling repository or a second generated-code root. Regeneration
removes the retired `src/generated/api/document-generation-gateway` output.
This change does not enable document generation
in the selected beta shell and does not claim DOCGEN-16 complete. The client
pins the Job Finder/saved-job boundary separately in ADR 0004. It must still
adopt the existing HttpOnly browser-session BFF model, implement accessible
draft preview and explicit approval, and remove the retained legacy generation
proxy before the feature is enabled.
